給兩個整數，在不用 `+`, `-` 的情況下實現兩數相加。

題目連結 🔗：[https://leetcode.com/problems/counting-bits/](https://leetcode.com/problems/counting-bits/)

### **問題分析**

這題就是在考加法器的基本原理，這邊直接進行一個上課的動作。

### **解題思路 - Bit Manipulation**

先從兩個正數的 case 講起，我們在做加法的時候就是把低位數加起來，再來做進位對吧？在 Bit 的世界中步驟是一模一樣的，舉個例子：

```
a = 5 = 0101
b = 3 = 0011
```

講解之前先定義一下 index

```
index = 3 2 1 0
a     = 0 1 0 1
b     = 0 0 1 1
```

所以等下如果提到第 0 個 bit 就是最右邊那位。

`a`, `b` 兩數要相加，`a ^ b` 的結果就是不管進位的話每個位數相加的結果，因為 XOR 意即相異為 1，相同為 0。

```
a   = 0101
b   = 0011
a^b = 0110
```

再來進位的部分要用 `a & b` 來看，如果兩個位數都是 1，表示需要進位，就會被標成 1，再來左 shift 一格後就可以給下一輪用。

```
a   = 0101
b   = 0011
a^b = 0110
a&b = 0001 -> 0010
```

所以經過這個步驟，第 0 位就搞定了，再來就是把這兩個結果當成新的 `a`, `b` 繼續加，完整流程長下面這樣：

```
a   = 0101
b   = 0011
a^b = 0110          (新的 a)
a&b = 0001 -> 0010  (新的 b)

a   = 0110
b   = 0010
a^b = 0100          (新的 a)
a&b = 0010 -> 0100  (新的 b)

a   = 0100
b   = 0100
a^b = 0000          (新的 a)
a&b = 0100 -> 1000  (新的 b)

a   = 0000
b   = 1000
a^b = 1000          (新的 a)
a&b = 0000 -> 0000  (新的 b)

a   = 1000
b   = 0000
```

當 `b` 為 0，表示沒有位數需要進位，加法也就結束了，而最終答案就是 `a`，這題來看 a = 0b1000，也就是 8。

再來要聊聊這個解法實際上負數也可以成功，首先先解釋一個 binary 可以有 signed int 跟 unsigned int 兩種解讀方式，舉 4-bits 來說，如果是 unsigned int，可以表示的 range 就是 `0 ~ 15`，像這樣：

```
0000 -> 0
0001 -> 1
0010 -> 2
0011 -> 3
0100 -> 4
0101 -> 5
0110 -> 6
0111 -> 7
1000 -> 8
1001 -> 9
1010 -> 10
1011 -> 11
1100 -> 12
1101 -> 13
1110 -> 14
1111 -> 15
```

但如果是 signed int，在 c++ 中一般都是用 two's complement，那可以表示的 int 範圍就是 `-7 ~ 7`，two's complement 的原理就是如果數字 `x` 需要取負數，那他的 binary 表示就是 `-x = ~x + 1`，也就是所有位數先相反過來然後結果再加一，結果如下：

```
0000 -> +0
0001 -> +1
0010 -> +2
0011 -> +3
0100 -> +4
0101 -> +5
0110 -> +6
0111 -> +7
1000 -> -8
1001 -> -7
1010 -> -6
1011 -> -5
1100 -> -4
1101 -> -3
1110 -> -2
1111 -> -1
```

可以看作是最左邊的位數如果是 1 表示是負數，是 ０ 表示是正數。

上面加法器的原理是可以完全不修改應用在 two's complement 上的，以 4-bits 為例，如果今天要實現 (-5) + 3，用 signed int 的表示方式會表示成這樣：

```
-5 = 1011
3  = 0011
```

而 `1010` 實際上就是 11，而 11 + 3 的結果是 14，也就是 `1110`，也就是 -2。看到這邊可能會想問說，那這種情況下，11 + 3 跟 -5 + 3 不是 binary 的表示法就一樣了嗎？這樣要怎麼分辨哪個是哪個？但實際上不會遇到這個問題，因為在 signed int 的世界中，4-bits 不會出現 11，所以根本就沒有辦法操作 11 的加法，因此不會有這個問題出現。

以上就是加法器的原理，知道原理之後實作就簡單了。

**Time Complexity** - `O(1)`<br>
**Space Complexity** - `O(1)`

#### **Implementation**

```cpp
int getSum(int a, int b) {
    while (b != 0) {
        int carry = (a & b) << 1;
        a = a ^ b;
        b = carry;
    }
    return a;
}
```
